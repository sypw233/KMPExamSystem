## BUG-20260516-001: 学生端可参加考试列表空态错误

| 字段 | 内容 |
|------|------|
| 严重程度 | P0 |
| 模块 | 学生端 / 我的考试 |
| 状态 | 已确认 |
| 影响 | 学生无法从 UI 进入考试, 阻塞考试答题闭环 |
| 发现版本 | Android 模拟器当前安装包 |
| 关联用例 | STU-EXAM-004, STU-EXAM-005, STU-EXAM-006 |

### 复现步骤

1. 使用 teacher1 创建课程、题目、考试并发布。
2. 将 student1 加入课程。
3. 使用 student1 登录 Android App。
4. 进入底部“考试”。
5. 点击刷新。

### 预期结果

“可参加”Tab 显示已发布且进行中的 `E2E考试-0516152720`。

### 实际结果

App 显示“暂无考试 / 还没有可参加的考试, 请稍后再来”。

### 后端对照

`GET /api/exams/my-available` 使用 student1 token 返回 200, 且 `data.content` 包含考试ID 104。

### 证据

- `screenshots/09-student-exams-after-data.png`
- `dumps/09-student-exams-after-data.xml`
- `test-data.json`

### 初步判断

客户端可能没有正确解析分页结构 `Page<ExamResponse>` 的 `content` 字段, 或刷新后 ViewModel 状态未更新到 UI。

## BUG-20260516-002: ADB 自动化输入 Compose TextField 不稳定

|------|------|

## BUG-20260516-003: 教师批改详情页客观题得分显示为 0

| 字段 | 内容 |
|------|------|
| 严重程度 | P1 |
| 模块 | 教师端 / 答卷批阅 |
| 状态 | 已确认 |
| 影响 | 教师批改时看到的客观题分数与提交记录总分不一致, 易误判 |
| 关联用例 | TCH-GRADE-004 |

### 复现步骤

1. student1 提交考试 104, 单选题自动判得 40 分。
2. teacher1 进入考试管理 -> 进行中 -> 批阅与记录。
3. 点击 Alice Student 的提交记录进入批改详情。

### 预期结果

批改详情顶部显示客观题得分 40。

### 实际结果

批改详情顶部显示“客观题得分: 0”, 但提交记录页显示总分 40。

### 证据

- `screenshots/13-teacher-grading-records.png`
- `screenshots/14-teacher-grade-detail.png`

### 初步判断

提交记录中的 `totalScore` 与批改详情页使用的 `objectiveScore` 字段来源不一致。后端返回 `objectiveScore = null`, 客户端显示为 0。

## BUG-20260516-004: 智能组卷弹窗默认题库值疑似使用历史编辑数据

| 字段 | 内容 |
|------|------|
| 严重程度 | P1 |
| 模块 | 教师端 / 智能组卷 |
| 状态 | 已确认 |
| 影响 | 可能误导教师选择错误题库 |
| 关联用例 | TCH-COMP-005 |

### 复现步骤

1. teacher1 进入考试管理。
2. 在未开始考试卡片点击“智能组卷”。
3. 查看弹窗中“题库”字段默认值。

### 预期结果

题库下拉框显示当前可用题库名称, 且不应残留历史编辑字段。

### 实际结果

题库字段显示“更新后的题库名”, 看起来像历史编辑测试数据或默认选择不明确。

### 证据

- `screenshots/16-teacher-random-compose-dialog.png`
- `dumps/16-teacher-random-compose-dialog.xml`

### 初步判断

可能只是已有测试题库名称, 也可能是题库下拉默认值缺少上下文。建议补充题库ID/题目数量展示, 降低误选风险。
